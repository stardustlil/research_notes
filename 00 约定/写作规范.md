# 写作规范

原则：**数学推导是唯一标准**。每句话要么是定义，要么是推导，要么是结论；代码只是把定义翻译成张量运算。不写背景铺垫、重复总结和与推导无关的工程细节。

## 目录与命名

```
首页.md
00 约定/        符号约定 · 写作规范 · 模板/
01 归一化/      归一化（总览）· BatchNorm · LayerNorm · RMSNorm
02 注意力/      注意力（总览）· Self-Attention · MHA
03 位置编码/    位置编码（总览）· Learned-PE · Sinusoidal-PE · RoPE · YaRN
attachments/    图片
```

| 对象 | 规则 | 例子 |
| --- | --- | --- |
| 主题目录 | `两位编号 中文主题`，编号即阅读顺序 | `03 位置编码/` |
| 主题总览 | 与目录同名，去掉编号 | `位置编码.md` |
| 概念笔记 | 论文中通用的英文名或缩写，多个词用 `-` 连接 | `RoPE.md`、`Sinusoidal-PE.md` |
| 约定笔记 | 中文 | `符号约定.md` |
| 附件 | 小写英文，`-` 连接，以所属笔记命名 | `sinusoidal-pe.png` |

- 目录只有一层，不建子目录；主题内的阅读顺序写在总览里。
- 中文名写进 `aliases`，不写 `tags`（目录已经表达分类）。
- 一级标题：概念笔记写「英文名（中文名）」，其他写中文。

## 概念笔记大纲

二级标题名称和顺序固定，不加序号（其他笔记会按标题名链接，如 `[[RoPE#推导]]`）。

| 位置 | 必选 | 内容 |
| --- | --- | --- |
| 标题下 | 是 | 一个公式块写出核心定义；有前置时上一行写 `前置：[[...]]` |
| `## 动机` | 是 | 1–3 句：上一种方法在数学上缺什么 |
| `## 定义` | 是 | 输入及形状、本篇局部符号、按计算顺序的公式；新矩阵首次出现标注 $\mathbb{R}^{\cdots}$ |
| `## 推导` | 是 | 每个 `###` 是一条结论，正文是它的推导 |
| `## 代码` | 是 | 最简可运行实现 + 验证 |
| `## 辨析` | 否 | 只写会导致算错的差异：与论文 / PyTorch 的写法差别、易混的维度或符号 |

不设「总结」「相关笔记」节：标题下的公式就是总结，关系在正文中链接。

## 主题总览大纲

| 位置 | 内容 |
| --- | --- |
| 标题下 | 一句话：本主题的方法共享什么数学结构 |
| `## 顺序` | 用 `→` 串起本主题笔记 |
| `## 对比` | 一张表，只放结论 |

## 代码

- 写函数而不是类，参数显式传入；只依赖 `torch` 和 `math`。
- 不做输入检查、dtype 转换、缓存、设备管理等工程处理。
- 变量名与数学符号对应（见[[符号约定#数学与代码对照]]），关键行行尾注释形状 `# [B, n, d]`。
- 代码块末尾用 `assert` 验证：有 PyTorch 对应实现时与之比较，否则验证正文推导出的性质。
- 复用其他笔记的函数时，在开头注释来源。

## 公式

- 标题中不写公式（会让章节链接失效）。
- 新符号先在[[符号约定]]登记，再使用。
- LaTeX 细则见[[符号约定#LaTeX]]。
